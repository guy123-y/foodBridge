# FoodBridge 🍞

פלטפורמת ווב לחיבור בין עסקים ופרטיים שיש להם **עודפי מזון** לבין מי שיכול **לאסוף** אותם (עמותות, מתנדבים, אנשים פרטיים) — כדי להפחית בזבוז מזון.

## תכונות עיקריות
- **הרשמה והתחברות** עם שם משתמש וסיסמה (Firebase Authentication)
- **כרטיס פרופיל** — חשבון פרטי או עסקי (שם חברה, אתר, טלפון)
- **פרסום מזון** — כותרת, כמות, טרי/לא טרי, כתובת איסוף (השלמה אוטומטית), ומועד אחרון לאיסוף
- **לוח פרסומים** — צפייה בכל המזון הזמין
- **מחזור חיים של פרסום:** `זמין` ← `ממתין לאישור` ← `אושר לאיסוף` ← `נאסף`
- **קוד איסוף בן 4 ספרות** — גלוי רק למפרסם ולאוסף המאושר, ומאמת את המסירה בפועל
- **"הפרסומים שלי" / "האיסופים שלי"** — מעקב אחר הפעילות האישית

## טכנולוגיות
| שכבה | טכנולוגיה |
|---|---|
| Frontend | React 18, React Router 6, Vite |
| Backend | Firebase Authentication, Cloud Firestore |
| כתובות | Photon (OpenStreetMap) להשלמה אוטומטית |

## אבטחה
כל ההרשאות נאכפות בצד השרת באמצעות [firestore.rules](firestore.rules):
- רק משתמש מחובר עם פרופיל יכול לפרסם או לבקש איסוף
- לא ניתן לבקש איסוף של פרסום שלך, או של פרסום שפג תוקפו
- בקשת איסוף היא אטומית — שני משתמשים לא יכולים לתפוס את אותו פרסום
- רק המפרסם יכול לאשר / לדחות / לסמן כנאסף
- קוד האיסוף נשמר בתת-אוסף נפרד שרק המפרסם והאוסף יכולים לקרוא

## התקנה והרצה
```bash
npm install
npm run dev
```
ואז לפתוח את הכתובת שמוצגת בטרמינל (בדרך כלל http://localhost:5173).

### חיבור לפרויקט Firebase משלך (אופציונלי)
1. Firebase Console ← Authentication ← Sign-in method ← להפעיל **Email/Password**
2. ליצור **Firestore Database**
3. Firestore ← Rules ← להדביק את תוכן `firestore.rules` וללחוץ **Publish**
4. להחליף את ה-config בקובץ `src/firebase.js`

## מבנה הפרויקט
```
src/
├── components/     # מסכים ורכיבים (התחברות, לוח, טופס פרסום, פרטי פרסום...)
├── context/        # AuthContext - ניהול המשתמש המחובר
├── firebase.js     # חיבור ל-Firebase
├── utils.js        # פונקציות עזר (תאריכים, סטטוסים, בדיקת סיסמה, קוד איסוף)
└── App.jsx         # ניתוב
firestore.rules     # חוקי האבטחה של מסד הנתונים
```
